# 도보 500m 도달권 — 경로 추출·보정 방법 요약 (2026-09-07)

지도에 그려지는 학교별 "도보 500m 도달권"이 어떻게 만들어졌는지, 무엇을 보정했고 무엇은 보정하지 않았는지를 한 장으로 정리한다. 상세 수치·비교 그림은 `docs/methodology_notes.md` §3·§3b 와 `reports/figures/walkshed_v3_compare_20260906.png` 참고.

## 1. 왜 직선 반경이 아닌가

직선 반경 500m 원은 담장·하천·간선도로·막다른 골목을 무시한다. 같은 500m 원 안에 공원이 있어도 실제 보행 경로로는 700m를 돌아가야 하는 학교가 있다. 그래서 "정책 도달성"은 보행 네트워크 위에서 실제로 걸어서 닿는 범위로 계산한다.

## 2. 세대별 방법 (무엇이 바뀌었나)

| 세대 | 방식 | 한계 | 현재 용도 |
|---|---|---|---|
| v1 OSMnx convex hull | 500m 안 노드들의 볼록 껍질 | 실제 도달 영역이 아님, 노드 적은 학교는 비정상적으로 작음 | 폐기 |
| Valhalla 등시선 (`isochrone_valhalla.geojson`) | 공개 라우팅 서버의 pedestrian 등시선(polygons) | 격자 등고선 일반화로 과대 경향(v3 대비 중앙값 1.24배), 외부 서버 의존 | **봉인 분석값 분모** (공원 수·면적·녹지율) |
| v2 OSMnx 노드 컷오프 (`school_isochrone_500m.geojson`) | 노드 기준 500m 컷 + 도로선 25m 버퍼 | 경계에 걸친 도로가 통째로 빠지거나 통째로 들어감, 가시(tendril)형, 학교 중심을 노드에 스냅 | 보존(비교용) |
| **v3 exact edge trimming** (`school_walkshed_500m_v3.geojson`) | 아래 §3 | OSM 보행로 누락은 동일 | **지도 표시 레이어** |

## 3. v3 추출 절차 (`scripts/accessibility/build_walkshed_500m_v3.py`)

1. **보행 그래프**: OSMnx `network_type="walk"`, 인천 전체(노드 78,571 · 엣지 216,190, 2026-09-06 수집). Overpass 기본 서버는 인천 전체 다운로드 시 타임아웃 → kumi.systems 미러 사용.
2. **잡음 제거**: 노드 30개 미만 고립 컴포넌트(학교 부지 내부 보행로 조각 등 2,020 노드)는 스냅 대상에서 제외. 섬 지역 네트워크는 유지.
3. **출발점 보정**: 학교 좌표를 최근접 **노드**가 아니라 최근접 **엣지에 투영**한다. 투영점까지의 직선 오프셋(중앙값 37m, 최대 186m)과 엣지 양끝까지의 선형 거리를 초기 비용으로 넣은 가상 출발 노드를 만든다. → 캠퍼스 중심~도로 사이 거리를 무시하던 v2 오차 제거.
4. **탐색**: 가상 출발 노드에서 다익스트라, cutoff 500m.
5. **엣지 절단(핵심)**: 각 도로 엣지에서 500m 안에 실제로 닿는 구간만 `shapely.ops.substring`으로 잘라 수집. 엣지 전체 도달 조건은 `(d_u + d_v + len)/2 ≤ 500`. → 경계에 걸친 도로의 "닿는 앞부분"이 정확히 들어가고 나머지는 빠진다.
6. **표현 보정**: 부분 엣지 35m 버퍼 합집합 → 20,000㎡ 이하 내부 구멍 채움 → 2m 간소화 → 535m 원으로 클립. 분리된 조각은 모두 유지. 엣지가 하나도 없을 때만 원으로 대체(이번 실행 0건).

## 4. 결과 (272개교)

| 지표 | 값 |
|---|---:|
| 500m 원 대비 면적비 (평균 / 중앙값 / 최소 / 최대) | 0.335 / 0.325 / 0.060 / 0.683 |
| v3 ÷ v2 면적 중앙값 | 1.284 (v2보다 작은 학교 24개교) |

즉 직선 반경 500m 원의 평균 1/3만 실제로 걸어서 닿는다.

## 5. 보정하지 않은 것 (의도적)

- **분석 봉인값은 재계산하지 않는다.** 35m 버퍼·구멍 채움은 "표시용" 보정이라 담장·하천을 덮을 수 있다. 공원 수·면적·녹지율·case 판정의 분모는 기존(Valhalla/v2) 파일을 그대로 쓴다.
- **아파트 단지 내부 보행로 누락**은 v3도 반영하지 못한다. 이는 `school_walk_500m_apartment_adjustment_20260504.csv`의 아파트 투과성 보정 시나리오(단지 개방 가정 시 녹지율 변화)로 별도 표시한다.
- **학교 출입구 좌표**가 없어 중심점 투영으로 대체했다.
- 2026-09-11 정정: 카카오맵 공식 REST API에 `/v2/routing/walk` 도보 경로가 추가되어 기존 키로 실제 호출에 성공했다. 종전의 “보행 경로 API 미제공” 설명은 현재 유효하지 않다. 일괄 등거리권 폴리곤 API는 확인되지 않았으며, 점간 경로 검증부터 적용한다. `scripts/accessibility/kakao_walk.py`, `data_processed/education/route_review.json` 참고.
