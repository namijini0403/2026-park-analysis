# 질문 해석·요소 선택·공간 비교 점검

사용자가 질문한 학구도와 도보 500m권의 불일치 비교에서 공원·녹지가 후보로 노출되고, 여러 요소 선택과 중요도 설정이 어려운 문제를 공통 흐름에서 수정했다.

## 확인한 원인과 변경

| 원인 | 변경 |
|---|---|
| ‘초등학교’의 ‘학교’만으로 공원·녹지 자료가 연관 후보가 됨 | 학교급은 범위로 처리하고 질문에 나온 주제·지표로 후보를 고름. 후보별 관련 이유 표시 |
| 일반 ‘도보’ 질문에 공원 경로를 연결 | 공원까지의 경로를 명시한 경우에 공원 경로를 연결. 보행권은 별도 자료로 연결 |
| 목록·상관분석·관측값 정렬에도 동일한 가중치 화면 노출 | 직접 조회, 요소 검토, 단일 관측값 정렬, 경계 중첩 비교로 분기 |
| 지도에서 고른 학교가 전체 상위 목록 요청을 제한 | 전체·학교별·상위/하위·가장 등의 요청 범위를 먼저 해석 |
| 초등 보행권 파일이 공통 보행권 조회에서 누락 | `school_walkshed_500m_v3.geojson`과 `education/walkshed_500m.geojson`을 함께 조회하고 두 파일 해시를 공개 |
| 자료 추가 버튼을 눌러도 선택 상태가 후보에 남지 않음 | 기본 체크박스, 선택 개수, 선택 카드 색, 다시 눌러 해제, 다른 자료에서도 동일 상태 유지 |
| 중요도를 하나만 바꾸면 나머지 미설정으로 서버 오류 | 중요도 설정을 선택 사항으로 접고, 켜면 선택·추가·첨부 요소 모두 보통에서 시작 |
| 응답 대기 중 작성한 다음 질문이 지워짐 | 전송한 질문만 전송 시 비우고, 응답 완료 시 새 입력을 지우지 않음 |
| 기록 조회에서 질문 조건이 사라짐 | 원래 질문의 주제와 요청 연도·지역·학교급을 유지 |

## 계산과 해석

경계 비교는 EPSG:5179로 변환한 공식 학구도와 기존 보행망 도달권의 면적 교집합을 계산한다. 기본 기준은 `100 × (1 − 교집합 면적 / 합집합 면적)`이다. 학구도 중 보행권 밖 비율, 보행권 중 학구도 밖 비율로 변경할 수 있다. 매우 넓은 학구는 기본 기준의 차이가 크게 나올 수 있으므로 목적에 맞는 분모를 선택해야 한다.

학교 ID로 연결된 여러 학구는 합집합으로 처리한다. 원형 반경이나 유치원 보행권으로 대체하지 않는다. 빈 도형·잘못된 도형·중복 보행권·미확보 자료·요청 연도 불일치는 보류한다. 일반 지역과 도서·농어촌을 나누며 경계의 표시값 동점은 함께 표시한다.

현 스냅샷 초등학교 272개 중 266개 계산 가능, 6개 보류를 확인했다. 이는 학생 거주 분포, 실제 출입구 통학 경로, 지원 우선순위의 검증이 아니다. 학교 종합점수는 만들지 않으며 안전·이용 자격·실행·출입구 경로 조건은 독립적으로 남긴다.

요소의 중요도는 검토 비중과 요소 표시 순서에 반영한다. 수치의 원래 값·연도·단위를 바꾸거나 학교별 투자 점수로 합산하지 않는다. 미설정이면 요소별 분포와 양쪽 관점을 함께 표시한다.

## 검증 위치

- `tests/test_question_relevance.cjs`: 공통 질문 유형, 42개 자료 접근, 불필요 후보 배제, 전체 범위, 실제 중첩, 다른 기준, 연도 미확보.
- `tests/test_boundary_measures.py`: 동일·불연속·부분 중첩·구멍·다중 도형·빈 도형의 독립 검산.
- `tests/test_hitl_analysis.cjs`: 42개 항목 실제 계산, 결측·중복, 가중치, 첨부, 안전 게이트, 선택/해제 UI.
- `tests/test_data_catalog.cjs`: 42개 항목 실제 조회, 출처, 학교급·지역·연도, 공시 지표 상관분석.
- `tests/test_question_input_race.cjs`: 응답 대기 중 작성한 다음 질문 보존.
- `tests/test_simple_chat.cjs`, `tests/test_observation_restore.cjs`, `tests/test_chat_workspace.cjs`: 기존 질문·이전 저장값·지도와 차트 회귀.
- `tests/verify_question_workflow_browser.cjs --live`: 운영 API와 카카오맵, 실제 여러 요소 선택·해제·중요도·재분석·모바일·연속 질문.

운영 검증 결과와 응답은 `outputs/hitl-relevance/live/`, 계산 검산은 `outputs/hitl-relevance/backend.json`에 기록한다. 최종 배포 해시와 상태는 `outputs/hitl-relevance/release-manifest.json`, `deployment.json`으로 확인한다.
