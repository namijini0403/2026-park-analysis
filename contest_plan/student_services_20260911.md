## 판단 구조

1. **현재 관측 공백**: 학교 중심 기존 500m 도로망 도달권 안의 시설 ID·개수. 직선 500m 개수와 최근접 직선거리를 따로 기록한다. 실제 이용 가능성·정원은 미확보다.
2. **학교 내부 자원**: 도서관 설치는 학교 장서 부족, 도서 지원은 장서 부족과 사서 부재를 따로 본다. 운동·복지의 내부 가용 공급은 미확보로 남긴다. 운동부·수상·복지지원학교 지정 여부로 학생 개인 수요를 추정하지 않는다.
3. **현재 규모**: 학교별 최신 확보 공시 학생 수와 해당 연도. 학생 수 미확보는 0으로 대체하지 않는다.
4. **미래 수요 신호**: 기존 2029 재학생 예측의 증가 신호. 시설 이용 수요 예측이 아니며 기본 가중치 0. 사용자가 조정할 수 있다.
5. **접근 마찰**: 직선권 안 시설이 있는데 도로망 도달권 안에는 없으면 경로·출입구 개선 검토로 분기한다. 시설 신설로 자동 연결하지 않는다.
6. **대안·후보**: 기존 시설 연계·운영 보완, 학교 개방·순회도서, 장서 구입·사서 지원, 접근 경로 개선, 복합화·신설을 구분한다.

점수 초기값: 관측 공백 60, 학생 규모 25, 내부 부족 15, 미래 0. 합계로 정규화한다. 장서 목표 20권/학생, 규모 기준 600명, 미래 증가 신호는 20% 증가에서 최대다. **법정 기준이나 최적 투자비율이 아니라 조정 가능한 계획 가정**이다.

- 시설 공백 성분: 도로망 내 관측 0개면 1, 1개 이상이면 0. 실제 서비스 충분성을 뜻하지 않는다.
- 장서 부족: `max(0, 1 - 학생당 장서/설정 목표)`.
- 학생 규모: `min(1, 현재 재학생/설정 기준)`.
- 도서 지원의 내부 성분: 사서합계가 0이면 1, 그 외 0; 결측은 미확보.
- 미래 신호: `min(1, max(0, (2029 예측/현재 학생-1)/0.2))`.
- 점수 하한: 확보 성분의 가중 기여 합계. 상한: 미확보 성분이 최대인 경우. 통계적 신뢰구간 아님.

같은 사업 안에서만 점수를 비교한다. 하한이 같으면 공동 순위, 구간이 겹치면 우열 미확정이다. 가중치·장서 목표를 바꾸면 점수와 조사 방향, 상위 10교 변화가 갱신된다. 장서·사서 부족을 도서관 건물 신설 하나로 해소한다고 가정하지 않는다.

## 후보 시뮬레이션

공원 추천 상위 후보만 재사용하지 않고, 기존 도서관 250m 격자 7,304개 중 학교 직선 500m 안에 있는 2,121개를 사용했다. 도서관·운동·돌봄별 관측 공백 학교 ID와 재학생 규모를 계산한다. 장서 지원은 학교 단위다.

후보의 숫자는 **관측 공백 학교 재학생 규모**다. 거주 인구·실제 신규 수혜자·보행 접근 인구가 아니다. 기존 도서관 후보 격자의 선정 범위도 그대로 상속한다. 설치 가능한 모든 토지를 탐색한 것이 아니다. 여러 후보를 선택하면 학교 ID 합집합을 사용한다. 선택 후보들의 숫자를 단순 합산하지 않는다.

신설의 토지 용도·면적·소유·취득비·운영비·인허가·출입구·안전경로·잔여정원은 미확보. 따라서 출력은 담당자가 조사할 후보이며 자동 설치 결정이 아니다.

## 파일과 재현

```powershell
python -m scripts.education.fetch_student_services --offline
python -m scripts.education.build_student_service_priorities
python -m unittest discover -s tests -p test_student_services.py
node tests/test_student_services_ui.cjs
```

새 수집은 `fetch_student_services --refresh`로 한다. 주소 API 키는 기존 `KAKAO_REST_KEY`/리포 외부 키 파일을 재사용하며 출력·원문·캐시에 기록하지 않는다. 캐시만 재현할 때는 키가 필요 없다. 원문 구조·필수 자유이용 근거가 바뀌면 실패 처리하여 기존 정상 파생 산출물을 유지한다.

- `data/student_services/raw/`: 공식 원문과 URL·수집시각·SHA256 메타.
- `data/student_services/geocode_cache.json`: 주소 질의와 결과.
- `data_processed/student_services/facilities.json`: 수집 시설 원장·제외 범위·프로그램 근거.
- `data_processed/student_services/priorities.json`: 학교 4개 판단·후보·입력 해시·출처.
- `data_processed/student_services/school_priorities.csv`: 기본 조건의 1,088개 학교×사업 결과.
- 화면 **현재 조건 JSON 저장**: 사용자 가정·점수 성분·선택 후보·입력 해시·한계 저장.

출처 등록부에는 수동 갱신으로 명시했다. 기존 도서관·학교 공시 자동 갱신과 새 파생 레이어의 자동 재계산은 아직 연결하지 않았으므로 해당 원천 갱신 후 빌더를 다시 실행해야 한다. 2026-09-11 무신청 운동시설 교체와 함께 기존 Railway 운영 서비스에 배포했다.
