# 학구도·공개자료 갱신·교육청 문서 통합

작업 기준: 2026-09-11. 실행 코드는 `park-railway-deploy/`이며 이전 제출용 프로젝트는 변경하지 않았다.

## 학구도

- [한국교육시설안전원 공개자료 목록](https://schoolzone.emac.kr/publicData/publicDataList.do)의 2026-03-20 기준 SHP 4종과 학교–학구도 연계 CSV를 수집했다. 게시일은 2026-05-19다. 지도 서비스의 현황 기준일과 다운로드 파일의 기준일을 구분한다.
- 인천 초등 통학구역·공동통학구역 279개, 중학교 학구·학군 25개, 고등학교 학교군 7개: 합계 311개. 인천 고등 비평준화지역 도형은 해당 공개파일에 0개다.
- 학교 연계표가 연결된 구역은 309개, 미연계는 2개다. 구역 수는 학교 수가 아니다.
- 공식 공개 대상은 초·중·고다. 유치원은 경계를 만들어 넣지 않고 `not_published`로 표시한다. [제공 범위·주기](https://schoolzone.emac.kr/publicData/dataInfo.do).
- PRJ를 읽어 WGS84로 변환하고 표시용으로 2m 단순화했다. 오류 도형 1개는 `make_valid`로 보정했으며 면적 변화 한도 0.1% 검사와 보정 표시를 남겼다. 공동·일방 구역 코드를 보존했다.
- 지도에서 **지도 표시 → 정책·개발 정보 → 공식 학구도**를 켠다. 학교급 선택을 따라 구역을 표시하며 클릭하면 연결 학교·자료 기준일·공식 출처를 확인할 수 있다.
- 학구도는 학교 중심 직선/도보 500m 생활권과 별도다. 경계나 포함 관계로 실제 배정 대상·안전도를 자동 확정하지 않는다.

산출물: `data_processed/education/school_zones.geojson`.
재현: `python scripts/education/fetch_school_zones.py data_processed/education/school_zones.geojson`.

## 공개자료 갱신 점검 및 개선

출처 등록부 17종을 검사했다. [상세 감사 JSON](data_refresh_audit_20260911.json)은 파일 경로·감시 방식·자동 반영 범위와 미등록 파일을 기록한다.

| 상태 | 등록 출처 수 | 실제 동작 |
|---|---:|---|
| 품질 통과 시 자동 반영 | 1 | 공식 학구도 전체 수집 → 검사 → 버전 생성 → 지도 반영 |
| 수집 후 검토 | 1 | 도서관 JSON API 전 페이지 수집·변경 감지 → 후보 → 관리자 검토 |
| 게시물 헤더 신호만 감시 | 12 | HTTP 헤더 변경 알림. 실제 첨부 수집·전체 파생분석 자동 갱신은 보장하지 않음 |
| 수동 | 3 | 원천 경로/어댑터 미확정. 자동 반영하지 않음 |

`data_processed`의 미등록 CSV/JSON/GeoJSON 1,065개에는 다수의 파생·분할 산출물도 포함된다. 독립 원천 1,065개가 빠졌다는 의미는 아니다. 전체 데이터가 자동 최신화된다는 표현은 아직 맞지 않는다.

이번에 고친 문제:

1. 첫 페이지가 같으면 뒤쪽 변경을 놓치던 JSON API 감시를 전체 페이지 해시 비교로 수정했다.
2. GeoJSON 후보의 속성 컬럼 목록이 비어 정상 파일도 '전체 컬럼 삭제'로 잘못 차단되던 문제를 수정했다.
3. 스캔 기준 상태를 기존 영속 저장소의 메타에도 보존한다. 재배포 후 기준선을 잃지 않는다.
4. 운영 서버의 기본 검사 주기는 1일이다. 명시적 환경변수 `0` 또는 관리자 저장 설정이 우선한다. 동일 프로세스에서 겹친 스캔을 건너뛰며 개별 수집 실패도 상태에 실패로 표시한다.
5. 학구도는 최신 게시물의 첨부 ID를 재탐색하고 ZIP 원문 해시·학교 연계표를 비교한다. 제공 서버의 ETag/Last-Modified가 있으면 조건부 다운로드로 전송량을 줄인다.
6. 학구도 자동 반영은 품질 정상·스키마 동일·구역 수 변화 20% 이내·기준일 역행 없음 조건을 요구한다. 큰 변경은 검토 대기, 실패는 이전 자료 유지다. 이 기준은 정책 판정이 아니라 수집 운영 규칙이다.
7. 미리보기 서비스의 `/app/data`에 영구 볼륨을 연결하고 서버 수면을 끈다. 문서·스캔 기준·staging·버전·감사 로그가 재배포 후 유지되는 구조다. 서비스는 단일 복제본을 전제로 한다. 여러 복제본으로 늘릴 때는 공유 DB 잠금이 추가로 필요하다.

관리 화면의 `/api/update-center/coverage`에서 인증 후 최신 등록 범위를 확인할 수 있다. 모든 출처의 재수집·정규화·모델 재학습·파생분석까지 연결된 것은 아니다. 특히 기존 `rebuild_command` 경로의 파생 파일 전체 트랜잭션은 별도 보강 대상이며, 이번 자동 반영 경로에서는 재빌드 명령이 있는 출처를 허용하지 않는다. 갱신된 지도 데이터는 새 페이지 로드에서 반영된다(일반 공개자료 HTTP 캐시 최대 5분).

## 교육청 파일과 기존 자료의 결합

**공개자료 갱신 화면 → 교육청 Excel·Word·한글 자료 함께 분석** 또는 `/office-documents.html`로 연다. 관리자 토큰을 사용한다.

1. 파일 읽기: XLSX·XLS·CSV·DOCX·HWPX·HWP·TXT, 최대 15MB. 파일 SHA-256이 같으면 기존 추출 결과를 재사용한다.
2. 표 미리보기와 연결 조건 확인: 표·머리글 행·학교 열·수치 열·학교급·기준연도·단위·기존 비교 지표를 지정한다.
3. 학교 ID 또는 같은 학교급 내 유일한 정확 학교명으로 결합한다. 중복 학교 행, 비수치, 미매칭은 제외 내역으로 남긴다. 0은 유효값이고 빈값은 결측이다.
4. 교육청 수치를 요청 범위의 별도 변수로 넣고 기존 분석 엔진으로 상관·산점도를 계산한다. 기존 환경·공시 값을 덮어쓰지 않는다. 표본 부족이나 일정한 값은 '미산출'로 돌려준다.
5. 본문 자료는 학교명·ID가 언급된 문단과 기존 학교 환경·공시자료를 함께 보여준다. 본문을 지시문으로 실행하거나 정책 점수로 바꾸지 않는다.
6. 결과 JSON에는 문서 해시·공개자료 해시·표/행/열·연도·연결/제외 내역을 남긴다. 관리자 저장소의 추출 문서는 화면에서 삭제할 수 있다. 원본 바이너리는 별도 저장하지 않는다.

형식별 한계:

- DOCX·HWPX 표를 지원하지만 병합 셀·다단 머리글은 미리보기에서 확인해야 한다.
- HWP 5는 본문과 표 셀의 텍스트 근거 연결을 지원한다. 표를 수치 분석하려면 HWPX/Excel로 저장한다. 암호·배포용 HWP, 구형 DOC, 이미지 OCR은 지원하지 않는다.
- XLSX 수식은 실행하지 않고 비수치로 제외한다. XLS는 저장된 계산 캐시 값을 읽는다.
- 자동 지오코딩·모호한 학교명 추측·문서 내용에 따른 모델 재학습은 하지 않는다. 수치 분석의 연도·단위는 담당자가 확인한다.
- 파일 내용은 외부 AI에 보내지 않는다. 파서 시간·압축해제 크기·행/열·텍스트 크기를 제한하며 XML 외부 엔터티를 차단한다.

## 실서비스 검증

- [지도](https://education-living-area-preview-production.up.railway.app/) · [교육청 자료 분석](https://education-living-area-preview-production.up.railway.app/office-documents.html). 현재 시연 관리자 토큰은 기존과 같은 `2026`이다.
- 최초 패키지에서 서버 공통 통계 자산 누락으로 502가 발생했다. 실행용 `assets` 포함, 배포 폴더에서 서버 모듈 로딩 검사, HTTP healthcheck 설정을 추가하여 수정했다.
- 수정 배포 `628ee0bd-a57d-4e9a-adad-ddbe4a462dc6`의 `SUCCESS`와 실제 파일 5종 해시 일치, 서버에서 XLSX 12개교 수치 결합·DOCX/HWPX 근거 연결·검증 문서 삭제·비인증 401·비공개 경로 404를 확인했다. [실서비스 검증 JSON](data_integration_live_validation_20260911.json).
- 서버 기본 스케줄은 실제로 1,440분·활성 상태다. 서버가 공식 SHP/CSV를 직접 수집해 품질 통과한 `v001`을 자동 반영하고 영구 저장소에 보존했다.
- 최초 로컬/서버 비교에서 원문 ZIP 5종 해시는 모두 같고, 좌표 마지막 자리만 최대 `2.84e-14`도 차이가 있었다. 최초 `v001` 생성은 실행 환경별 정규화의 미세한 수치 차이이며 공식 학구 자체가 바뀌었다는 뜻이 아니다. [정규화 비교](zone_normalization_comparison_20260911.json).
- 최종 배포 `a474f581-33bc-4df5-a88d-385ca8b5d99c`의 `SUCCESS`를 확인했다. 재배포 뒤 검증용 문서가 그대로 조회됐고, 활성 학구도 `v001`을 오류 없이 복원하여 이전과 같은 SHA-256을 유지했다. 검증 문서는 삭제했다. [실제 재배포 보존 검사](live_persistence_20260911.json).
- 재배포 후 공식 원천을 다시 수집한 검사도 `unchanged=1`, 이벤트 0건으로 통과했다. 변하지 않은 자료에 중복 버전을 만들지 않는 것을 확인했다.
