# 질문 → 변수 체크 → 가중치 레버 → 근거와 결론

사용자 수정 요청을 기준으로 별도 지원안 입력 화면에서 질문 중심 흐름으로 변경했다.

## 화면에서 확인

`자료에 질문하기`에서 `전체 초등학교 도서관 지원을 검토해줘`를 입력한다. 장서 총수와 공공 어린이도서관 직선거리를 체크하면 두 개의 0~100 레버가 바로 나타난다. 장서는 작은 값, 거리는 큰 값 관점을 선택하고 80:20과 20:80을 비교한다.

- 장서를 중시하면 실제 장서 관측 학교와 도서 구입·교체·공동 이용 선택지를 제시한다.
- 외부 거리를 중시하면 실제 거리 관측 학교와 연계 이용·순회대출·교내 독서 거점 선택지를 제시한다.
- 관측값 점을 누르면 해당 구간의 모든 학교·대상명과 실제 수치가 펼쳐진다. 점은 겹침을 줄이기 위해 표시 위치만 묶는다. 연도·학교급·단위·도서지역을 분리한다.
- 변수 변경은 500ms 후 자동 분석하며, 가중치만 변경하면 이미 받은 자료 스냅샷에서 브라우저가 재계산한다. 추가 분석 API·LLM 호출은 없다.
- 질문·변수·방향·가중치·결과는 주제별로 현재 브라우저에 저장된다. 저장 당시 기록은 현재 추천으로 자동 복원하지 않는다.
- 모든 가중치가 0이거나 변수를 전부 해제하면 이전 답변을 현재 결과로 남기지 않는다.

## 계산과 정책 판단

검토 비중은 `개별 가중치 / 선택 가중치 합 × 100`이다. 같은 비중이면 병렬 선택지를 유지한다. 결론은 가장 중시한 변수의 실제 관측, 선택 방향, 검토 가능한 정책 방안을 연결한다. 추가 변수들의 근거도 바로 아래에서 확인한다. 관측 최솟값·최댓값과 동점 학교를 공개하며 임의의 부족 기준을 만들지 않는다.

이용 대상·안전·실행·출입구 경로 검증을 가중치로 상쇄하지 않는다. 학교 종합점수나 무조건 지원 순위를 만들지 않으며, 결측·중복·선택 학교 유효값 미확보는 판단 보류한다. 제안한 방안은 검토 선택지다. 실제 지원 확정·물량 산정에는 기존 지원안의 근거 확인 절차를 사용한다.

기존 설치 추천지 자료 `docs/robust_xai_recommendation.md`, `ui-preview/src/SimulationPage.tsx`의 가중치 정규화·정책 선호 변화·근거 분해 구조를 참고했다. 과거 후보 점수를 전체 학교의 투자 순위로 재사용하지 않았다.

## 구현 및 검증

- `assets/hitl-analysis.js`, `.css`: 체크·레버·자동 갱신·한 흐름의 화면.
- `assets/question-conclusion.js`: 서버와 브라우저가 공유하는 결론 계산, 변수별 관측·선택지, 클릭 가능한 점 분포.
- `api/_hitl_analysis.js`: 관련 변수 확장, 0~100 가중치 검증, 출처별 비교 범위·결론 제공. 이전 1~3 가중치 API 유지.
- `tests/test_question_levers.cjs`: 서버/브라우저 계산 일치, 가중치에 따른 선택지 변화, 실제 대상 값, 동점, 별도 도서지역, 누락, 0·잘못된 가중치, 안전·과거 값 검증.
- `tests/test_hitl_analysis.cjs`: 42개 자료 영역, 첨부, 계산, UI 회귀 통과.
- `tests/test_question_relevance.cjs`: 질문 분류·범위·272개 학교의 실제 학구도/보행권 비교 및 누락 검증 통과.
- `tests/test_policy_studio.cjs`, `tests/test_observation_restore.cjs`: 기존 지원안·저장값 정책 회귀 통과.
- `tests/verify_question_levers_browser.cjs`: 실제 Edge에서 체크, 레버, 자동 결론, 가중치 변경 시 네트워크 호출 없음, 점 클릭 학교 목록, 모바일, 주제 복원 검증.
