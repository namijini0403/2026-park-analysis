이 기록은 이전 `workspace_ux_optimization.md`의 브라우저 미검증/연결 차단 상태를 대체한다. 전용 Playwright MCP로 실제 Railway 배포 화면을 조작했다. 기존 CUA에는 사용 가능한 브라우저가 없었지만, 별도 브라우저 제어 경로를 확보해 실제 카카오 지도와 공개 데이터로 검증했다.

## 최종 사용자 흐름

1. 학교급·지역·학교 검색으로 선택한다. 지도는 기본적으로 학교만 표시하며, 축소 상태에서는 가까운 학교를 수로 묶는다.
2. `지도 표시`에서 공원 도보권·도서관 주변·학원 주변 또는 개별 항목을 선택한다. `학교만`으로 추가 표시를 초기화한다.
3. 학교를 선택하면 간단한 정보 패널이 열린다. 지역 요약과 초등학교의 독서·지정·주변 맥락은 필요할 때 펼친다. 상세 리포트는 명시적인 분석 버튼으로 연다.
4. `질문 분석`에서 질문을 실행하면 설명과 시각화 위치로 이동한다. 예시·조건 변경·계산 근거·과거 분석은 접어서 보여 준다.
5. 통계 비교, 공개자료, 시뮬레이션, 가이드 등 기존 기능은 유지한다.

## 실제 화면에서 발견하고 수정한 문제

- 기본 축척에서 큰 학교 마커가 겹침: 군집화 시작 축척을 10에서 8로 변경하고 일반 마커를 24px로 줄임.
- 학교를 골라도 지역 통계가 먼저 나옴: 선택 학교를 우선 표시하고 지역 요약은 접음.
- 초등학교 상세 준비가 끝난 뒤 리포트가 자동으로 열림: 자동 열기를 제거하고 다른 학교급과 동작을 통일함.
- 밝은 패널과 기존 어두운 설명 배경의 대비 문제: 패널 색상 변수와 상태 배지·지표의 글자색을 함께 조정함.
- 모바일 지도 설정과 검색 영역이 동시에 화면을 덮음: 설정을 펼친 동안 검색 영역을 숨기고, 학교 패널을 열면 지도 표시 버튼이 상세 내용을 덮지 않도록 숨김.
- 화면 크기 변경 시 지도 중심 이동: 이전 크기에서 확정한 중심을 보관하고 SDK의 크기 변경 이벤트로 생기는 임시 중심을 제외해 재배치함. [Kakao 공식 relayout 설명](https://apis.map.kakao.com/web/sample/mapRelayout/)도 확인함.
- 모바일 질문 화면의 과도한 여백·긴 예시 목록: 입력 조건을 한 줄로 배치하고 예시를 접으며 결과로 자동 이동함. 산점도 축 글자를 확대함.
- 좁은 통계 표의 과도한 줄바꿈: 열이 많은 표는 내부 가로 스크롤과 안내를 제공함.
- 모바일 가이드 제목과 인쇄·닫기 버튼 겹침: 본문 시작 위치를 조정함.
- 자료 로딩 직후 통계를 열면 빈 현황이 고정됨: 로딩 중에는 안내를 표시하고 분석 진입을 보류함.
- Railway에서 존재하지 않는 Vercel 분석 스크립트와 favicon 요청: 배포 환경 조건과 내장 아이콘을 적용함.
