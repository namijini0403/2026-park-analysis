# 질문에서 사용자 선택을 거치는 분석

## 화면 흐름

‘자료에 질문하기’에서 질문하면 고려 요소 선택을 기본으로 연다. ‘질문 후 고려 요소를 직접 선택하기’를 해제하면 기존 직접 조회가 가능하다.

1. 질문과 현재 학교급·선택 학교·연도를 확정하고 관련 자료 영역을 제시한다.
2. 사용자가 영역 안의 요소를 선택한다. 전체 보유 자료 영역에서도 추가할 수 있다. 선택은 자동 확정하지 않는다.
3. 각 요소의 반영 방식, 현재 관측/미래 가정/접근 조건/후보 관측 구분, 결측 처리 방법을 확인한다.
4. 방향은 양쪽 관점/낮은 값 검토/높은 값 검토, 중요도는 미설정/낮음 1/보통 2/높음 3이다. 언제든 제외할 수 있다.
5. CSV·TSV·Excel 첨부에서 연결 열을 설정해 여러 요소를 추가한다. JSON·CSV·TSV 붙여넣기 및 현장 메모도 지원한다. 첨부 요소에도 방향·중요도를 설정한다.
6. 분석 버튼을 누르면 현재 원자료로 다시 계산한다. 조건이 바뀌면 이전 결과 재보기 버튼은 비활성화되며 재계산해야 한다. 계산 중 변경한 조건에 오래된 응답을 적용하지 않는다.
7. 근거 패널에서 분포·원값·백분위·검토 비중·출처를 확인한다. 검토 조건과 전체 결과를 JSON으로 저장할 수 있다.

## 계산 계약

- 기본 종합점수와 전체 학교 투자 순위를 만들지 않는다.
- 중요도를 하나라도 설정하면 첨부를 포함한 모든 선택 요소의 중요도를 지정해야 한다. 검토 비중은 `중요도 / 중요도 합계 × 100`이다. 미설정 요소에 임의 기본값을 넣지 않는다.
- 가중치는 검토할 요소의 비중이다. 학교별 원값을 가중 합산해 투자 점수로 바꾸지 않는다. 현재 근거로 이용·안전·실행·출입구 경로를 모두 검증할 수 없으므로 정책 결정은 보류한다.
- 방향 미설정에서는 낮은 값과 높은 값의 분포를 함께 제공한다. 방향을 선택하면 그 방향의 원값 백분위를 별도 열로 계산한다.
- 이 값 이하 비율 = `같은 비교 집단에서 값 이하인 유효 관측 수 / 유효 관측 수 × 100`. 이 값 이상 비율도 동점을 포함한다. 장서가 많을수록 우선지원이라는 뜻이 아니다.
- 학교급·연도·시나리오·공시 세부 지표·단위·종목·대회·반경·선행기간을 분리한다. 도서·농어촌 별도 검토 집단도 분리한다.
- 자료 없는 학교를 0으로 넣지 않는다. 같은 집단의 동일 대상 중복값은 모두 제외한다. 결측 인구 셀이 있는 추정값도 제외한다. 분모는 확보한 유효 관측이며 전체 학교 전수조사로 표시하지 않는다.
- 장서 총수·좌석 수는 기존 장서 CSV에서 학교 ID, 공시연도, 일치 확인을 만족할 때만 연결한다. 공시 비율은 해당 공시 수치 그대로 사용하고 2026 학생 수로 다시 나누지 않는다.
- 공시 지표는 개별 세부 지표별 선택을 제공한다. 기록형·지도형 자료는 별도 근거 요소로 제공하며 등급을 숫자로 바꾸지 않는다.
- 첨부는 기존 연결 검증을 통과한 범위의 관계와 분포다. 공식 확인 데이터로 승격하지 않는다. 현장 메모는 확인할 조건으로 기록하며 안전 통과 증거로 자동 변환하지 않는다.
- 화면 표는 학교별 다요소 관측 12행, 개별 결과 20행까지 표시하며 전체 결과는 검토 JSON에 보존한다. 그래프 집계는 유효 관측 전체를 사용한다.

## 공통 구조와 확장

- `api/_hitl_analysis.js`: 기존 `_data_catalog` 42개 영역과 `_data_answers`의 정규화 어댑터를 재사용한다. 요소 정의·계획·검증·계산을 담당한다.
- `api/chat.js`: `hitl_plan`, `hitl_options`, `hitl_run` 세 액션만 연결한다. 기존 직접 채팅 동작은 보존한다.
- `assets/hitl-analysis.js`, `assets/hitl-analysis.css`: 기존 채팅 폼의 기본 제출에 요소 선택 단계를 제공한다. 기존 첨부 파서와 근거 시각화를 재사용한다.
- `index.html`: 새 JS와 CSS 로딩만 추가한다.
- 영역 후보 연결은 현재 카탈로그의 명칭·키워드와 목적별 확인 규칙에 근거한다. 등교 안전·독서·돌봄·공원·미래 수요 질문에는 추가로 필요한 자료를 안내한다. 공원 경로를 통학 경로로 해석하지 않는다. 이 단계에 추가 LLM 호출이나 새로운 모델은 사용하지 않는다. 미확인 요소를 AI가 임의로 만들어 계산하지 않는다.
- 학교별 선택 요소를 함께 보는 관측표를 제공한다. 학교명 순이며 선택 학교는 먼저 표시한다. 서로 다른 단위·연도·시나리오를 합산하거나 학교 투자 순위를 산출하지 않는다.
- 첨부 연결 상태는 결과 표의 열 이름으로 확인한다. 연결된 수치의 사용자 자료 분포를 추가하고, 지정 방향에 맞는 백분위를 계산한다. 기록형 요소의 비중 차트에는 자료 영역명을 표시한다.
- 새로운 영역을 카탈로그에 등록하고 기존 정규화 어댑터를 제공하면 같은 흐름을 사용한다. 새 숫자 필드는 의미와 단위를 카탈로그에 정의해야 한다. 금지된 과거 점수·등급·추천 필드는 제외한다.
- 검토 계획과 중요도를 localStorage에서 자동 복원하지 않는다. 클라이언트가 보내는 점수·추천·안전 통과 주장은 채택하지 않으며 버전이 다른 요청은 거절한다.
- 소스 SHA-256, 실제 적용 요소·방향·검토 비중·요청 범위·메모를 결과에 포함한다. 최대 16개 기존 요소, 첨부 5개, 전체 요청 900KB다.

## 검증과 동시 작업

새 테스트: `node tests/test_hitl_analysis.cjs` — 42개 영역 실행, 장서 실제 원값, 백분위 동점, 결측/중복, 미설정/명시 가중치, 안전 비상쇄, 구형 데이터 차단, 첨부 연결, 선택/제외/재계산 UI.

브라우저: `PLAYWRIGHT_MODULE`을 설치된 playwright-core 경로로 지정한 뒤 `node tests/verify_hitl_browser.cjs`. 별도 임시 포트의 읽기 전용 테스트 서버를 사용하며 기존 실행 서버·배포 산출물·갱신 스케줄러를 건드리지 않는다.

변경은 새 모듈 위주로 격리했다. 기존 작업 디렉터리의 다른 수정은 되돌리거나 커밋하지 않았고 배포하지 않았다.
