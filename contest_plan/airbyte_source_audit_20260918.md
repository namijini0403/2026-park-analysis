# Airbyte 활용 및 자동 업데이트 연결 점검 — 2026-09-18

## 결론

홈페이지마다 API 키가 필요한 것은 아니다. 공개 JSON, 파일, 게시글을 읽을 수 있으면 키 없이 수집·변경 감지가 가능하다. API 키가 필요한 원천은 해당 기관의 활용신청이 별도로 필요하며 Airbyte가 그 권한을 대신하지 않는다.

Airbyte는 원자료 수집·적재 계층에 적합하다. 기존의 좌표 변환, 학교ID 결합, 500m 공간분석, 커버리지 검증, 안전·실행 조건, 승인·버전·롤백을 대체하지 않는다. 현재 앱에서는 먼저 기존 수집기 결함을 고치는 것이 효과적이다.

## 확인 범위와 증거

- 현재 앱: https://education-living-area-preview-production.up.railway.app
- 구 앱: https://park-analysis-web-production.up.railway.app
- 운영 API에서 스케줄, 원천별 마지막 검사, 저장소 상태를 읽었다. 수정 전 기록: `outputs/source-audit-20260918/runtime-before.json`.
- 현재 앱의 자동 감시 주기는 24시간, 구 앱은 12시간으로 설정되어 있었다. 설정 ON은 모든 원천이 정상이라는 뜻이 아니다.
- 현재 앱은 파일 저장소와 `/app/data` 영구 볼륨을 사용한다. 구 앱은 Postgres를 사용한다. 구 앱 DB가 현재 앱의 저장소라고 혼동하면 안 된다.
- manifest의 19개 등록 원천과 앱 전체 데이터는 같지 않다. 등록되지 않은 자료와 파생 산출물이 별도로 있다.

## Airbyte 적용안

사용자가 제공한 모두의 AI 실험실 화면에서 Airbyte 이용신청 및 Source/Destination 설정 가이드를 확인했다. 파일 소스와 Postgres 목적지 안내가 있다. 단, 안내 화면이 실제 계정에 제공되는 모든 권한을 보증하지는 않는다.

권장 흐름:

`공개 API/공개 파일 → Airbyte → 별도 원자료 테이블/저장소 → 현재 앱 정규화·품질 검사 → 재계산 후보 → 기존 검토/반영 절차`

- 첫 실험은 **인천 공원 또는 건축 착공 원자료 1종**으로 제한한다. 기존 정상 수집기를 중복 운영하는 것보다 아직 미연결된 원천을 시험한다.
- 원자료 저장에는 수집시각, 원천 URL, 기준일, 원본 해시, 행 수, 수집완료 여부를 보존한다.
- 좌표 누락·미수집은 0이나 부족으로 바꾸지 않는다. 도서학교와 출입구·경로 확인을 그대로 유지한다.
- 현재 분석 테이블을 Airbyte destination으로 직접 덮어쓰지 않는다. 원자료 저장과 운영 DB를 구분하고 별도 쓰기 권한을 사용한다.
- 수정일 커서가 없는 파일은 전체 스냅샷 비교가 필요하다. ‘동기화 성공’은 ‘자료가 최신’ 또는 ‘분석 검증 완료’와 다르다.

사용자가 할 일:

1. 실험실에서 Airbyte 이용신청 및 본인 인증. 계정 활성화 후 접속 주소를 공유한다(비밀번호나 API 키를 채팅에 붙이지 않음).
2. 제공 기간, 예약 작업 상시 실행, 외부 HTTPS 접근, 외부 Postgres/S3 연결, Connector Builder/맞춤 커넥터 허용 여부를 이용 가이드나 담당자에게 확인한다.
3. LOCALDATA·KESS·파일형 착공 자료는 최신 원본의 다운로드 경로와 이용 조건을 확보한다. API가 제공되는 경우에만 해당 데이터의 활용신청을 진행한다.
4. Aside 설치는 필수가 아니다. 로그인된 화면의 신청·다운로드 자동화가 필요할 때 브라우저 제어 연결로 사용할 수 있지만 서버의 정기 수집을 대신하지 않는다.

이용신청 목적 문구 예시:

> 인천 학교 주변 야외활동 환경 분석 서비스의 공공데이터 수집을 실증하고자 합니다. 공개 원자료 1종을 Airbyte로 주기 수집하여 별도 원자료 저장소에 적재하고, 수집 이력·원본 해시·누락 여부를 확인합니다. 정책 판단과 분석 결과 반영은 기존 서비스의 품질 검증 및 사람의 검토 절차를 유지합니다. 외부 HTTPS 원천, 외부 Postgres/S3 목적지, 예약 실행 및 맞춤 커넥터 이용 가능 여부 확인을 요청합니다.
